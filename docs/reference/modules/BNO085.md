# BNO085 Sensor Hub

[Documentation hub](../../README.md) · [Current system readiness](../../SYSTEMS.md)

## Major firmware functions

| Function | Contract |
|---|---|
| `AtlasBno085_Init()` | Releases hardware reset, opens the official CEVA SH-2 stack, installs callbacks, and requires at least one product-ID entry. |
| `AtlasBno085_EnableReport()` / `DisableReport()` | Changes one SH-2 feature report with explicit microsecond interval and batch latency. |
| `AtlasBno085_Service()` | Drains no more than eight pending SHTP service phases per foreground call, dispatches decoded values, and returns a typed failure if servicing adds an I/O, protocol, decode, or asynchronous-reset fault. |
| `AtlasBno085_OnInterrupt()` | Records the active-low interrupt and its TIM2 timestamp in constant-time ISR context; it performs no I2C transaction. |
| `AtlasBoard_GetBno085Sample()` | Copies the latest decoded value by SH-2 sensor ID and optionally consumes its availability bit. |

Source: [`atlas_bno085.h`](../../../App/Inc/atlas_bno085.h), [`atlas_bno085.c`](../../../App/Src/atlas_bno085.c), and the provenance-controlled [CEVA SH-2 library](../../../ThirdParty/CEVA/sh2/README.md).

## Validation state

The first physical-board log on 2026-09-03 showed BNO identity status `ATLAS_ERROR_IO`, no report enables, and no BNO samples. The board straps SA0 low, but firmware had been addressing `0x4B`; this was corrected to seven-bit `0x4A` (STM32 HAL value `0x94`).

The follow-up `atlas-20260903-230631.jsonl` still retained BNO identity `ATLAS_ERROR_IO` and zero accepted BNO reports. The operator saw one transient dashboard value before or outside the retained status sequence; the log itself does not contain that sample. More importantly, the MS5611 on the same I2C1 bus stopped after eight samples and accumulated I/O errors immediately after the BNO probe. The earlier wrong-address run did not strand the barometer. That evidence is consistent with the correct-address BNO transaction reaching the two-phase read path, followed by a stale payload-ready edge causing one extra no-data read and leaving the STM32 I2C path unusable.

Version `1.0.1` replaced that transport with CEVA's reference sequence: read and return the four-byte SHTP header, wait for the next H_INTN assertion, then read and return the complete continuation transfer. After either read phase, a still-LOW pin is treated as the tail of the consumed assertion—not as new data. Only a new falling-edge callback or a physically observed HIGH-to-LOW cycle authorizes the next read, preventing a phantom continuation or third transaction. A terminal BNO HAL error holds U12 in reset before deinitializing/reinitializing I2C1 and restoring its generated filters, protecting the shared MS5611 path. The owner reports that follow-up board operation streams correctly; this is initial functional evidence, not calibration, long-run, timing, or shared-bus qualification. Version 1.0.2 retains the same BNO correction.

The shared timebase start is idempotent: GNSS reuses the TIM2 handle already started by this driver, preserving its count and capture configuration. A review probe covers that [R01 correction](../../REVIEW_REPORT.md#r01-gnss-startup-restarts-an-already-running-timer). Host tests exercise held-LOW interrupt tails, the exact header/idle/continuation/idle sequence at CEVA's 1,024-byte maximum, shifted `0x94` address, write guard, terminal timeout, reset-low state, shared-bus reinitialization and filter restoration. An end-to-end test runs this adapter with the actual vendored SH-2/SHTP parser through reset, four product records and four feature writes. A separate silent-response test proves product-ID discovery returns `SH2_ERR_TIMEOUT` instead of spinning forever.

## RTOS access

The active-low EXTI callback only marks work pending. `AtlasIO` services at most eight SHTP reads per cycle and consumes the latest accelerometer, calibrated gyroscope, calibrated magnetic field, and rotation-vector reports into four named snapshot fields. Check the corresponding `ATLAS_RTOS_VALID_BNO_*` bit, use the matching `bno_*_received_at_ms` field for MCU-clock sample age, and separately inspect the SH-2 timestamp and accuracy for report quality. An asynchronous hub reset latches board service failure because volatile feature reports were lost; application code cannot clear that failure by reading the driver directly.

## Board contract

| Item | Atlas value |
|---|---|
| Fitted part | BNO085, U12 |
| Bus | I2C1, up to 400 kHz |
| 7-bit address | `0x4A` (HAL address `0x94`); U12 SA0/H_MOSI is strapped to ground |
| Reset | PB13 `BNO085_NRST`, active low |
| Host interrupt | PG0 `BNO085_H_INTN`, active low / EXTI0 |
| Timebase | Free-running TIM2 at 1 MHz, shared with GNSS PPS capture |
| Boot bound | 4,000 ms measured from the start of the reset/open sequence, including the requested reset hold |
| I2C retry policy | Three attempts; each timeout is 50 ms margin plus rounded 100 kHz wire time (51 ms for the header and 143 ms at CEVA's 1,024-byte maximum); 1 ms retry/write guard |
| Product-ID operation bound | 5,000,000 us in the locally patched CEVA operation table |
| Foreground bound | At most eight SHTP service phases per `AtlasBno085_Service()` call |

The CEVA SH-2 implementation is process-global/singleton. Atlas supports exactly one BNO085 instance.

## Startup and transport behavior

1. Start the 1 MHz timer.
2. Assert reset for 10 ms, release it, and wait for active-low H_INTN.
3. Open CEVA SH-2 with the Atlas HAL adapter.
4. Register asynchronous-reset and sensor-event callbacks.
5. Request SH-2 product IDs and require a nonzero entry count.
6. At board level, enable these volatile reports:

| SH-2 report | Interval | Nominal rate |
|---|---:|---:|
| Accelerometer | 10,000 us | 100 Hz |
| Calibrated gyroscope | 10,000 us | 100 Hz |
| Calibrated magnetic field | 20,000 us | 50 Hz |
| Rotation vector | 10,000 us | 100 Hz |

SHTP-over-I2C length discovery is a two-interrupt state machine. The first active-low H_INTN permits exactly a four-byte header read; that fragment is returned to SHTP and its length/timestamp are retained. The driver performs no second transaction while H_INTN is high. A subsequent H_INTN permits the complete continuation read, which begins with a new SHTP header. The high continuation bit is removed before bounds checking and the repeated length must match. Frames larger than CEVA's supplied buffer are rejected; no heap allocation occurs. This sequencing matters specifically on BNO085: polling it when no data is available can clock-stretch the bus.

## Data contract

CEVA decodes each report into `sh2_SensorValue_t`:

- calibrated acceleration is in m/s^2;
- calibrated angular rate is in rad/s;
- calibrated magnetic field is in microtesla;
- rotation vector components are `i`, `j`, `k`, `real`, with accuracy in radians;
- `timestamp` is the SH-2 event timestamp in microseconds;
- `status` low bits report the SH-2 accuracy class from unreliable through high.

The board keeps one latest-value slot per sensor ID. A new report overwrites the previous slot and sets the corresponding availability bit. This is an intentional latest-value mailbox, not a lossless log.

```c
sh2_SensorValue_t value;

if (AtlasBoard_GetBno085Sample(&atlas_board,
                               SH2_ROTATION_VECTOR,
                               &value,
                               true))
{
    /* Check value.status, age, quaternion norm, and the verified frame transform. */
}
```

## Health and fault interpretation

| Counter | Meaning |
|---|---|
| `interrupts` | H_INTN edges observed by EXTI. |
| `transfers_read` / `transfers_written` | Complete successful SHTP transfers. |
| `io_errors` | Repeated I2C transaction failure. |
| `protocol_errors` | Invalid SHTP length/header relationship. |
| `decoded_samples` / `decode_errors` | CEVA decode outcomes. |
| `async_resets` | SH-2 reported an unexpected hub reset. Feature reports must then be treated as suspect until recovered. |
| `bus_recovery_attempts` / `bus_recovery_failures` | Attempts to restore shared I2C1 after a terminal BNO HAL transfer failure, and any incomplete restoration. |
| `last_hal_status` / `last_hal_error` | Retained STM32 HAL status and I2C error bit mask from the last terminal failure. |
| `last_failure_stage` / `last_transfer_length` | Failure location and implicated byte count. |

Bring-up status publishes these values in `bno.health`, along with `pending_length`, current active-low `intn_low`, and `initialized`. Failure-stage values are: 0 none, 1 header read, 2 full continuation read, 3 write, 4 header length, 5 continuation length, 6 I2C deinit, 7 I2C init, 8 analog-filter restore, and 9 digital-filter restore. A recovery attempt protects the shared bus; it does not silently declare the BNO healthy or retry the probe.

At board level, the first non-OK service result is latched in `runtime_fault`. The RTOS supervisor then withholds the independent watchdog refresh so an unexpected hub reset or newly detected transport/protocol failure cannot silently leave the system running on stale fused data.

## Bench acceptance

1. Verify PB13 reset width and PG0 active-low boot assertion.
2. Capture H_INTN and I2C1 together. Confirm address `0x4A` (HAL `0x94`), a four-byte header read, H_INTN reassertion, then one full continuation read. A retained LOW tail must not cause another read; the next phase requires a new falling edge or observed HIGH-to-LOW cycle.
3. Record every product-ID entry, software part/build/version, and reset cause.
4. Capture feature commands and at least 1,000 reports of each default type; verify rate, sequence continuity, units, and accuracy flags.
5. Slowly rotate the board through known orientations; verify quaternion norm/continuity and establish the sensor-to-body convention without guessing Euler order.
6. Force a hub reset and confirm `async_resets` changes, stale data is rejected by higher layers, and reports are deliberately re-established before use.
7. Hold H_INTN inactive and low in separate tests; confirm bounded boot failure and bounded foreground work/no interrupt storm. Inject a terminal transfer failure and confirm `recovery_attempts` increments, `recovery_failures` remains zero, U12 stays reset, and MS5611 sampling resumes.

## Known limits

- Default report setup is volatile and has no persistent dynamic-calibration policy.
- Shared-I2C recovery after a terminal BNO transfer failure is implemented, but the failed BNO remains reset/uninitialized. Hot BNO reprobe and automatic report re-enabling after an asynchronous SH-2 reset are deliberately not implemented; use a controlled board reset after retaining evidence.
- Latest-value storage can hide missed sequences unless the consumer checks sequence/timing.
- The RTOS supervisor checks each configured report's MCU receipt age (500 ms after applicable grace). No board/body transform, calibration acceptance or sensor-redundancy voter exists; fresh receipt does not establish report quality.
- The fused output must not be treated as independent evidence from the direct IMU/magnetometer without understanding shared physical error sources.
