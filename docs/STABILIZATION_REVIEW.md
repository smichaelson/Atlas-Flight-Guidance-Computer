# Stabilization 1.3.0–1.3.4 review

Three separate author review passes were performed for the fixed bench feature. These are self-reviews, not independent qualified approvals or a flight release.

## Pass 1 — geometry and control ownership

Traced physical PCB channels 7,8,1,2 to the shared TIM3 channels, the outward shaft convention and the sensor-to-board frame. An independent forward-kinematics search found an X tilt sign error in the initial inverse mapping; corrected it. The executable regression compares 289 attitudes × 4 shafts against all 101 whole-degree positions. It also checks neutral, reversal, clipping, singularities, nonfinite data, positive gyro rotation, bias subtraction, tick wrap, duplicates and stale samples.

The output service regression verifies no motion on boot-high, switch release/debounce, immediate falling-edge stop, all four timer routes, manual exclusion, 35 seconds without USB (beyond the manual timeout), stale/rail trips with no high-switch restart, queued-save cancellation and saved OFF.

## Pass 2 — persistence, host and browser

Reviewed the exact-length/version/CRC record, sync/close/readback, startup read-only behavior and single filesystem owner. Added short-write, sync, close, corrupt/short-read, missing-card, stale authorization and reserved-filename regressions. Replaced an early unbounded filename comparison with bounded validated case-insensitive reservation.

Host tests require the advertised stabilization profile and current connection/control epoch. They reject malformed multi-channel telemetry, invalid switches/power/sensor/card state and direct generic-command bypass. OFF remains available with stale/pending telemetry. Browser verification found a compact-poll response guard that discarded the new tab's replies; fixed it and added a regression. Manual tab-exit/visibility handlers no longer stop autonomous stabilization.

## Pass 3 — integration and failure cleanup

Reviewed the complete diff, other profiles, ISR stop fences, startup sequence, SD callback ordering, timer preload and watchdog paths. Added cleanup for a partially started four-channel group and coherent disabled telemetry after an emergency stop. Fault injection on the second HAL PWM start proves all pulse commands and pins are cleared. Generic output disable also fences autonomous restart.

Full Bringup/ServoBench, service, host and review suites pass. Instrument and stabilization UI tests pass. GNU normal Debug/Release, Bringup and ServoBench builds pass. The first normal build's packaging step failed because objcopy was absent from PATH; rerunning with the installed compiler's bin directory resolved it. No source workaround was needed. IAR source membership is updated; IAR compilation was not available.

Static stack frames in ServoBench Debug: control service 208 bytes, estimator 152, geometry 136, settings preparation 40, console dispatch 1104, storage read 656, storage save 712, storage task 1128. These are individual frames, not worst-case complete call chains. Live task stack margins are checked during bench verification.

## Smoothing revision 1.3.1

The owner clarified that the grinding-like sound occurred during tiny or continuously changing movements and requested slower/smoother commands. This is a working software hypothesis, not a confirmed acoustic or hardware diagnosis. The 1.3.0 capture did contain repeated 1–2 µs target changes near rest. Added a 6 µs target deadband, 100 ms command smoothing and a 60°/s slew bound. Output targets now advance at most once every 20 ms, while IMU, switch, freshness and power checks continue every 5 ms. PWM remains approximately 333 Hz. Manual workbench direct-position behavior and the persisted record format are unchanged.

Three additional author passes reviewed this revision:

1. **Numerical behavior:** ten seconds of alternating ±5 µs input produces zero output changes; monotonic full-range reversals reach both exact endpoints, each 20 ms step stays within 12 µs, and a slow continuous tilt remains tracked. Singularities freeze the actual current command, including an unfinished ramp. Invalid late-channel inputs leave all output/state values unmodified.
2. **Timing and stop behavior:** command shaping occurs outside the register critical section and is committed only after the existing cancellation/switch checks. Tests cross the 32-bit tick wrap, reject catch-up bursts after a late iteration, and stop on the first 5 ms switch sample between command updates. Every start resets shaping to the actual 1500 µs hardware start.
3. **Integration:** the full Bringup/ServoBench and normal service suites pass. ServoBench, Bringup, normal Debug and normal Release builds pass. The SD format and all four saved direction bits remain compatible. The controller's individual static stack frame is 224 bytes; MotionStep's is 80 bytes. These are not complete call-chain bounds.

The 233,776-byte ServoBench 1.3.1 image uses 122,984 bytes of DTCM including reserved memory. Frozen HEX SHA-256: `3deaf71d3220b0c7a9877b0b466587d0ccf5d400452e415fd5af8fa0bcc21764`. The matched board accepted and verified the flash write. USB did not immediately re-enumerate after the ROM start request. Following the owner's full power cycle with SW2 OFF, COM3 identified 1.3.1 with the same UID. The saved calibration, reversal mask 15 and disabled setting loaded correctly. Enabling was then saved/readback verified for the comparison.

The 323-frame physical comparison captured about 11 seconds of active output before reason 7 stopped PWM with SW2 still ON. Exact endpoints may make one smaller final correction. This trades static pointing precision and continuous slow motion for fewer small commands; quiet or smooth stabilization still requires an observed comparison. The IMU estimator, switch/power checks, SD record, direction mapping, 333 Hz pulse rate and manual workbench behavior are unchanged.

## Diagnostic revision 1.3.3

An attempted fast USB-driven PWM7 waveform on 1.3.2 was aborted when command acknowledgments exceeded the test's deadline. The console reserves bounded reply space before executing commands; a stream faster than its reply drain can drop commands. This attempt did not complete the waveform and provides no mechanical acceptance result. Stop was acknowledged, fresh telemetry confirmed PWM off, and the station was reconnected. No USB streaming retry was performed.

Added a separately requested, single-channel waveform generated by the output owner every 5 ms. Each accepted diagnostic runs exactly one 1- or 2-second sinusoidal cycle through nominal ±50°, returns to 1500 µs, and holds until the existing three-second idle cutoff. It requires SW2 OFF and an explicitly enabled full-travel channel, rejects overlapping sweeps and late session starts, and does not extend any output timeout. It bypasses the estimator to distinguish target timing from attitude estimation. Stabilization tuning remains unchanged and is still unaccepted.

Added a retained `fault_detail` for reason-7 stops, with dashboard descriptions, so a later comparison can identify the precise failed estimator check. Sensor thresholds, configuration schema and calibration/direction settings are unchanged.

## Continuous tracking revision 1.3.4

Replaced the 100 ms / 5° correction rule with direct 5 ms target updates during motion and independent rest detection for each shaft. A resting shaft starts tracking at 6 µs / 0.6° from its actual command. During tracking there is no minimum step or software speed limit. It returns to holding once targets stay within 3 µs / 0.3° of their retained reference for 150 ms. Very slow motion can still produce small corrections, with less than 0.6° hold error at each evaluated nonsingular destination. This is an experiment informed by the smooth native sweeps; stabilization acceptance remains pending.

Three further author review passes covered this revision:

1. **Numerical response:** tests cover 50 seconds of rest noise, direct full-range reversals, every-microsecond tracking at 200 Hz, independent stationary/opposing shafts, settling and noise rejection, arbitrarily slow accumulated motion, exact endpoints, singularity cleanup, tick wrap, late iterations and atomic state/output rejection on invalid inputs. Both 1- and 2-second native sine references are reproduced exactly at every evaluated 5 ms sample, without an added filter or ramp.
2. **Owner and interruptions:** rest state is reset from the actual neutral start and only committed with the corresponding PWM commands after the final cancellation/emergency/physical-switch checks. Production IO tests verify the 5 ms gate across tick wrap, direct current destinations, unchanged timer counter/control/update/channel registers and prompt switch stop. USB-independent operation, fault latching, saved OFF and partial-start cleanup regressions still pass.
3. **Integration:** full Bringup/ServoBench, service and UI suites pass. GNU ServoBench, Bringup and normal Debug/Release builds pass, as does the repository check. The diagnostic sweep, retained fault reporting, SD schema, direction mask and sensor/power limits are retained. ## Limits

The implementation is documented in [Stabilization](STABILIZATION.md). Actual horn directions and travel are not observable over USB. Sustained linear acceleration, single-axis geometry and nominal ±50° travel limit the achievable down direction. SD durability after sudden power interruption cannot be guaranteed by a successful earlier readback. A physical OFF-to-ON cycle is required after boot and faults. Scope measurements and physical tilt observation remain separate from software tests.
